# Live reference-game studies: de-identified trial data

Written and generated by Claude Opus 5.5 at the PI's request (2026-11-15); the export was checked
by script, not reviewed by a person.

Every live Prolific study the RSA campaigns ran: the closed campaign (October 2026,
`docs/auto_rsa/`) and the open campaign (November 2026, `docs/auto_open/`). One row per jsPsych
record each participant's page stored, for every submission received (the analysis's exclusions
are marked, not applied).

## De-identification

- **People** are identified by `person`, a keyed hash of their Prolific id (HMAC-SHA256, first 16
  hex digits). The same person has the same `person` in every study, so repeat participation is
  visible. The key and the map from Prolific id to `person` are kept only on Sherlock and on the
  PI's machine, never in this repository: without the key, someone who knows a Prolific id cannot
  find that person here.
- **Free text is dropped**: the end-of-study `comment` box of the open campaign (the closed
  campaign had none).
- Also dropped: Prolific's participant, session and study ids, and each trial's rendered HTML
  (`stimulus`; the display is in the structured fields, the pages are in the committed designs).
- Every other field is on an explicit whitelist (`src/rsa/share.py`); the export refuses any field
  not on it, and refuses to write a table containing any of the studies' Prolific identifiers.
  An independent pass over the written files found none of the 4,219 Prolific ids and no
  Prolific-shaped (24 hex digit) string.

## Files

- `people.csv`: one row per submission. `study`, `experiment`, `person`; `run_pseudonym` (the id
  the campaign's own committed records use: `live<k>` in a closed run, `p<k>` in the open
  campaign); `kept` (whether the run's analysis kept this person; empty for the closed pilot, which
  was not modelled); `n_records`; `submitted_at_client`; `list_index`.
- `trials/<study>.csv`: one row per jsPsych record (welcome, instructions, comprehension, practice,
  test and catch trials, the experience rating). `task` and `phase` say which; `rt` and
  `time_elapsed` are milliseconds; list-valued fields (`objects`, `feature_names`, `words`,
  `display_order`, ...) are JSON. The response fields are `choice`/`chosen_alt` (closed campaign)
  and `response` (open campaign: a JSON choice, rating pair or production choice by paradigm).
- `MANIFEST.json`: submissions and kept people per experiment, trial rows per study.

| study | what | submissions | kept | trial rows |
|---|---|---|---|---|
| `closed_pilot` | closed chain 0's design at N = 20 | 20 | (not modelled) | 320 |
| `closed_c0`-`closed_c2` | closed chains, 3 experiments each | 1,799 | 1,659 | 34,181 |
| `closed_final` | pre-registered final (OSF s48jv) | 1,225 | 1,108 | 23,275 |
| `open_pilot1` | open pilot 1 (first registration): bets, choice + rating, production (exp. 3 not finished) | 499 | 429 | 18,987 |

| **total** | 4,219 distinct people (896 in more than one study) | **5,396** | | **127,744** |

Not included: the open campaign's run-D2 smoke tests (rehearsal designs, 30 people).

The closed campaign's pre-registered data are spent for confirmatory claims
(`docs/auto_rsa/CONSOLIDATION.md` §5); stage 1's two chains share people by design.

## Regenerating

On Sherlock, with the key in `~/.auto-psych-private/`:
`python scripts/rsa/share_trials.py --out <dir>` (from a checkout; it reads each study's
`private/raw_collected/`).
