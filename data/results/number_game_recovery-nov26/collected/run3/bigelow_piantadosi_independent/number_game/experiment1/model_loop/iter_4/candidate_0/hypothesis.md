Refinement of `multiplicative_not_exponential_concepts`: people still build number concepts from simple primitives (a fitted cost per extra primitive, the size principle, Erlang-weighted intervals, near-all-or-none commitment to the best-explaining concept), with an extra cost on powers, squares and cubes. The one change is that "contains the digit d anywhere" is a hard, rarely entertained concept, because it ignores where the digit is written. It pays its own fitted prior cost, so people seldom commit to it. The sharpest disagreement with the best model is on sets whose examples all contain a digit d (e.g. 92, 82, 27, 42). There, people say no to targets that contain d without sharing an example's last digit (e.g. 23, 29, 12), while the best model predicts yes.
