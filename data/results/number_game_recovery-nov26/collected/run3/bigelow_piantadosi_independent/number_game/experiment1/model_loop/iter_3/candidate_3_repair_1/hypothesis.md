Refinement of `erlang_interval_simplicity_search`: people still build concepts from mental primitives (a fitted cost per extra primitive, the size principle, an Erlang size prior on intervals, near-all-or-none commitment to the best-explaining concept). The one change is that concepts read straight off the written numeral — "ends in 2", "contains a 7" — cost a different, fitted amount from arithmetic concepts that must be computed (primes, squares, cubes, powers, multiples of m), instead of every two-primitive rule costing the same. If digit-notation concepts are cheaper, people more readily read a set like 92, 82, 27, 42 as "ends in 2" with one stray, and reject numbers that only share a range with the examples or are merely odd/even neighbours of them.
