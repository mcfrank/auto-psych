Refinement of `multiplicative_not_exponential_concepts`: people still build number concepts from mental primitives (a fitted cost per extra primitive, a fitted extra cost on powers, squares and cubes, Erlang-weighted intervals, the size principle and near-all-or-none commitment to the best-explaining concept). The one change is how "contains the digit d" is represented: people read numerals by place value (tens digit, ones digit), so "contains d" is not an elementary property but a disjunction, "the ones digit is d OR the tens digit is d", and it costs one more primitive than "ends in d" or "multiples of m", priced by the same per-primitive cost with no new free parameter. So when every example contains a digit (e.g. 92, 82, 27, 42), people seldom commit to "contains 2" and say no to targets that contain the digit without sharing an example's ending (23, 29, 12), as the critique reports.
