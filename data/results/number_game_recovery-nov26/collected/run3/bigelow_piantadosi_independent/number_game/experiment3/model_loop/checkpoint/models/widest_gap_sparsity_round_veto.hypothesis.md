I refined `round_veto_spacing_sparsity` and kept all of it: the set-size-graded privileged-fives concept learner, the veto of round targets (10, 20, ..., 100) on a fitted share of trials when no example is round, and a fitted lowering of yes answers the sparser the program's output looks. The one change is how people judge that sparsity: not from the average gap between neighbouring examples but from the widest empty stretch between them, because a long run of numbers the program skipped is what signals that it produces few numbers. So a set with one big hole, such as 27, 42, 82, 92, makes people as reluctant to say yes as an evenly spread set with the same hole, even though its average gap is much smaller.
