The live number-game models enumerate every (set, interval) pair (~524k) and every (cell, interval) hit (~1.5M scatter), costing ~55-115 ms per gradient; several candidates (2026-10-31, experiment3 iter_1) were rejected "too slow to fit".
Fix used in pedagogical_teacher_sampling (iter_1/candidate_0_repair_1): an interval weight factors as G_k(a,b) (set-independent: width prior x W(a,b)^(-beta k), k = examples inside, 0..4) times a constant per region (intervals holding the same examples form a rectangle in (a,b)). Take 2D prefix sums of G_k and read rectangle sums by 4 corner gathers (~1.8k regions, ~7.5k target-clipped rectangles). Subtract per-k max of log G before exp. Gradient fell 114 -> 22 ms, p_yes identical to 1e-13; warm-start NUTS sampled 1000 iters/2 chains in 244 s.
**Why:** a second too-slow rejection is final for a slot.
**How to apply:** reuse for any candidate built on the interval machinery; also dedupe exception-neighbourhood member tables (pm.Data matrix @ weights) rather than per-concept gathers.
