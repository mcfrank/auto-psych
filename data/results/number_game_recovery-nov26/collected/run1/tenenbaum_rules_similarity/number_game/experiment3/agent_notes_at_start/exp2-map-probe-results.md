Experiment 2 (2026-10-30, iter_0 candidate_5): incumbent erlang_interval_size_family_prior MAP log-lik -2246.17 (per-set constant rate -2380, saturated -1787; members of the example set get only 62% yes, so the data are very noisy).
Each change below was added alone to the incumbent: lapse to 0.5 (lapse went to 0), learned example reliability (stayed at 0.90), learned weak/strong sampling mix (theta 0.9, slightly worse), offset arithmetic progressions (weight went to 0, even though many exp2 sets share a residue mod 3/4/5/6/12), digit-vocabulary concepts (weight went to 0), log-scale interval widths (-2262, much worse), Gamma shape on the width prior (no gain). None of these helps.
Primes in their own family on top of powers_own_family gained +0.35 nats; it was submitted as primes_own_family_erlang_interval.
**Why:** these probes save repeating dead ends.
**How to apply:** use scratch/resid.py-style find_MAP probes before writing a candidate. Gains probably need a different decision or noise structure, not more concepts.

Later probes (iter_0 candidate_4_repair_1): learned reliability (stays 0.9, near-duplicate rejected, RMSE 0.0005), log-odds decision distortion (gamma 1.0, bias 0), posterior/likelihood exponents (tau 1.0), Gamma shape (2.08), decade-aligned interval bonus (-0.87, +0.3 LL but RMSE 0.0019 < 0.002 novelty gate) all fail. iter_3 candidate_1 (2026-10-30, process brief), probes on without_replacement_size_principle (MAP LL -2245.12): leaky working memory (each example kept with prob r, averaged over subsets) r -> 1.0, dead. Family consideration sets (each family comes to mind with prob q_f, Bayes over considered families) ON TOP of the Dirichlet family prior: q -> 1 (shared or per family), dead. Availability REPLACING the family prior (equal prior per considered family): -2295 (Beta(1,1)) / -2299 (Beta(2,2)), about 50 nats worse; submitted as limited_family_consideration_set. Consideration-set trick: mix over all 255 non-empty subsets via p_subset @ per-subset softmax of family evidence, which is cheap. Probe script: iter_3/candidate_1/scratch/map.py (pass the MAP's transformed values to compile_logp).
Speed note (same candidate): the full 5302-concept posterior @ membership matmul costs 0.046 s/grad; regrouping intervals by (threshold?, width, n_inside) with a (sets, groups, 100) elementwise sum gave identical p_yes but 0.31 s/grad, so don't regroup a matmul model. Smoke check took 287 s (machine load ~13) and printed OK. Script /tmp/c5i3/cmp.py compares p_yes and grad time for two model files.
