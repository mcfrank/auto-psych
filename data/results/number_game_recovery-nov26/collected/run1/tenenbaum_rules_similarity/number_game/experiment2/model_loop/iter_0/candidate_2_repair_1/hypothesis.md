People hold a single running guess about the program (a rule or a numeric range, weighed by family plausibility and an Erlang prior on range width) and revise it example by example in the order shown: they keep their current guess with a probability that grows with how well it explains the newest example, and otherwise draw a fresh guess — but when they redraw they judge the "suspicious coincidence" (the size principle) only for the newest example, merely requiring the guess to cover the earlier ones. So evidence for tight concepts does not compound across examples as in an ideal Bayesian learner, and which example drives specificity depends on the order shown (the last examples, plus whatever guess has survived from the first).
