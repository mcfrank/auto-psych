# Critique context

# The task

Each participant sees a few example numbers between 1 and 100, produced by a
hidden computer program, and is asked about other numbers between 1 and 100:
would the program also produce this number? The examples on a trial are its
*set* (one to four numbers, shown in the order given); the number asked about
is the *target*. The participant answers yes or no. There is no correct
answer and no feedback.

Every participant answers about many (set, target) pairs, and the same set is
asked about with many targets.

## The data

Each row of `responses.csv` is one answer:

| Column           | Meaning                                                            |
| ---------------- | ------------------------------------------------------------------ |
| `number_set`     | the example numbers, comma-separated in the order shown ("16,8,64") |
| `target`         | the number asked about, 1-100                                      |
| `rating`         | 1 if the participant answered yes (the program would produce it), else 0 |
| `trial_index`    | the trial's position in that participant's session                 |

**Incumbent model code:** `/scr/wurgaft/auto-psych/agent_trees/88c1bd3cf1e5f7a8/repo/_runs/cell_1/experiment3/model_loop/models/heading_extrapolation_weber_width.py`
**Incumbent hypothesis:** Refinement of the incumbent `heading_direction_range_extrapolation`: people do Bayesian concept learning over the same arithmetic, digit and digit-sum rules and every numeric range of 1-100. They read the examples as distinct draws with some strays and sometimes guess, and they let the direction of the last step stretch the ranges they consider toward where the sequence is heading. The one change is in how they judge a range's breadth before any examples. They judge it Weber-like, by its width relative to the magnitude of the numbers it covers, not by its absolute width. So "60 to 70" counts as a tighter, more specific range than "2 to 12", and the strength of this preference is inferred. This predicts that generalization around large clustered examples falls off differently from generalization around small ones, while the heading effect, rule and digit-sum generalization are kept.
