People treat the task purely as rule induction: they weigh only the arithmetic and digit rules (odd, even, primes, squares, powers, multiples, "ends in d", "contains d") by how well each explains the distinct examples shown (the size principle, sampling without replacement), and when no rule fits they fall back on "the program produces any number at all", with occasional guessing. They never entertain numeric ranges, so this predicts no graded magnitude generalization: a target near the examples (e.g. 61 after 60, 62, 64) is no more likely to get a "yes" than a distant number that fits the same rules.
